# Telegram-бот Anime365 с личными списками просмотра

Бот работает на Ubuntu 24.04 с Docker Compose. Он принимает название аниме,
предлагает выбрать тайтл, серию, тип просмотра, конкретный перевод и доступное качество.
Затем скачивает поток, без перекодирования собирает MKV с выбранными субтитрами и
отправляет его разрешённому пользователю. Каждый пользователь может сохранить аниме
в личный список «Смотрю», продолжить с первой непросмотренной серии и получать
уведомления о новых сериях.

## Telegram Mini App

Mini App добавляет мобильный каталог поверх той же SQLite и того же клиента Anime365:
библиотека «Смотрю», поиск, выбор серии/перевода/качества, direct playback и
возобновление внутри серии. Обычный плеер получает свежую ссылку на конкретный
поток и обращается к CDN Anime365 напрямую; VDS не скачивает и не перекодирует
видео для такого просмотра. Кнопка fallback включает потоковый proxy с `Range`
только если WebView не может открыть CDN напрямую.

Если Anime365 вернул субтитры, Mini App добавляет их в плеер как same-origin
WebVTT track. Ссылка Anime365 остаётся на backend в короткоживущем owner-bound
ticket: это решает CORS ограничения Telegram WebView. ASS/SSA и SRT конвертируются
в WebVTT только как небольшой subtitle-файл; видео при этом не скачивается и не
перекодируется. В WebVTT fallback не сохраняются ASS-эффекты и позиционирование.

Доступ к Mini App имеют только `OWNER_ID` и ID из существующего bot allowlist.
Сервер проверяет подпись Telegram WebApp `initData` и никогда не принимает ID
пользователя от frontend. Поэтому `/allow <telegram_user_id>` открывает оба
интерфейса, а `/revoke` сразу закрывает их оба. Если у пользователя нет своего
токена Anime365, Mini App предлагает выполнить `/auth` через бота.

В `/start` появляется кнопка «Открыть каталог», когда задан `MINI_APP_URL`.
В BotFather задай этот же HTTPS URL как Menu Button или Main Mini App. DNS имени
из `WEB_DOMAIN` должен указывать на VDS, а порты 80 и 443 должны быть доступны:
Compose запускает Caddy, который получает и продлевает TLS-сертификат и публикует
только web frontend/backend. Внутренний ASGI-сервис наружу не открывается.

Бот остаётся закрытым: доступ есть только у владельца и пользователей из allowlist.
`OWNER_ID` (или старый `TELEGRAM_ID`) задаёт владельца и администратора. Владелец
всегда разрешён, даже если его нет в таблице allowlist, и его нельзя удалить командой
`/revoke`. Неавторизованные аккаунты не получают доступ к поиску, токенам или спискам.

В репозитории также остаётся [исходный shell-клиент](ani365-cli-master/README.md).
Логика запросов и поддержка вариантов ответа embed перенесены из этого клиента.
Лицензия: [GPL-3.0-or-later](ani365-cli-master/LICENSE).

## Установка на VDS

Для обработки одной серии достаточно 2 CPU, 4 ГБ RAM и около 30 ГБ SSD.
Видео не перекодируется, поэтому основная нагрузка приходится на сеть и диск.
Docker Engine и Compose plugin уже должны быть установлены. Домен и входящие
порты для бота не нужны: используются исходящие HTTPS-запросы и long polling.

После публикации этих изменений в GitHub:

```bash
sudo apt update
sudo apt install -y git curl jq
sudo git clone https://github.com/DrumDrumSpike/ani365-cli.git /opt/ani365-cli
cd /opt/ani365-cli
```

Помести свой `.env` в `/opt/ani365-cli/.env`. Если его ещё нет:

```bash
sudo cp --no-clobber .env.example .env
sudoedit .env
sudo chmod 600 .env
```

Текущие имена переменных из твоего `.env` поддерживаются:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` или `token_BotFather` | Токен Telegram-бота от BotFather |
| `OWNER_ID` или `TELEGRAM_ID` | Числовой ID владельца и администратора, не `@username` |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | Данные приложения с `my.telegram.org` для локального Bot API |
| `ANI365_BASE_URL` | Необязательно; по умолчанию `https://smotret-anime.app/api` |
| `WATCH_CHECK_INTERVAL` | Необязательно; интервал проверки новых серий в секундах, по умолчанию `600` |
| `WEB_DOMAIN`, `MINI_APP_URL` | HTTPS домен Caddy и публичный URL Mini App |
| `DOWNLOAD_WORKERS`, `DOWNLOAD_TTL` | Максимум одновременных offline jobs (по умолчанию 2) и TTL готового browser-файла |

Также поддерживаются `BOT_TOKEN` и `OWNER_ID`; если заданы, они имеют приоритет
над старым названием соответствующей переменной. `WATCH_CHECK_INTERVAL` должен быть
положительным целым числом. Токен Anime365 в `.env` не нужен: бот попросит его в
личном чате. Этот токен шифруется и сохраняется отдельно для каждого Telegram ID;
один пользователь не получает доступ к токену другого.

После первого запуска доступ есть только у владельца. Чтобы добавить человека,
владелец отправляет боту его числовой Telegram ID, например `/allow 123456789`.
Не добавляй в allowlist общедоступные чаты или неизвестные ID: бот рассчитан на
разрешённых пользователей в личных чатах.

При первом переходе с облачного Bot API сначала собери образ и выполни одноразовый
`logOut`. Команда читает токен из `.env`, поэтому он не попадает в историю shell:

```bash
sudo docker compose config --quiet
sudo docker compose stop bot
sudo docker compose build bot
sudo docker compose run --rm --no-deps bot python -m ani365_bot.migrate
sudo docker compose up -d --wait --wait-timeout 180
sudo docker compose ps
sudo docker compose logs --tail=50 telegram-bot-api bot
```

Не запускай `docker compose config` без `--quiet`: полный вывод подставляет и
показывает секреты из `.env`.

`migrate` требуется только один раз для данного бота при переходе с
`api.telegram.org` на локальный сервер. Это не миграция SQLite: в дальнейшем
схема базы обновляется автоматически при старте приложения. Первая сборка также
устанавливает `yt-dlp` и `ffmpeg`. После запуска открой своего бота в Telegram и
отправь `/start`. Один токен бота должен обслуживаться только одним запущенным
экземпляром; существующий webhook нужно снять перед переходом на long polling.
Бот сам его не меняет.

## Ручное обновление после commit и push

Для установки, запущенной командой `docker compose up -d --build`, обновляй
существующий каталог проекта после отправки изменений в ветку `main`:

```bash
cd /opt/ani365-cli
sudo git pull --ff-only origin main && sudo docker compose up -d --build --wait --wait-timeout 180
sudo docker compose ps
sudo docker compose logs --tail=50 telegram-bot-api bot
```

Команда скачает изменения, пересоберёт образ и пересоздаст контейнер, ожидая
его готовности. `.env`, база и ключ шифрования сохранятся. При старте Store
выполняет только прямые, недеструктивные миграции SQLite `v1 → v4` через `PRAGMA user_version`:
существующие пользователи и зашифрованные токены Anime365 не удаляются. В базе также
сохраняются allowlist, список «Смотрю», прогресс и состояние уведомлений, поэтому они
переживают перезапуск. Перед обновлением в рабочем окружении всё равно сделай резервную
копию Docker volume `ani365_bot-data`: для восстановления нужны и `bot.sqlite3`, и
`token.key`.

Незавершённый выбор аниме после перезапуска нужно начать заново. Повторный `git clone`
нужен только при первой установке; для существующего каталога используется `git pull`.

В этом режиме `deploy.env` не требуется. Скрипт `scripts/update.sh` предназначен
для опубликованных релизов, описанных ниже, и обычный push в `main` не устанавливает.
Создавать `.venv` и запускать проверки разработки для такого обновления тоже не нужно:
зависимости приложения устанавливаются внутри Docker-образа.

## Использование и очистка

- `/start`, `/help` — подключение Anime365 или справка.
- `/auth` — ввод/замена токена Anime365. Неверный новый токен не затирает старый.
- `/logout` — удаление сохранённого токена Anime365.
- `/cancel` — закрытие меню и отмена ввода токена.
- `/watching` — открыть личный список «Смотрю» без нового поиска Anime365.
- `/notifications` — открыть сохранённые аниме и их настройки уведомлений.
- `/allow <telegram_user_id>` — добавить пользователя в allowlist; только для владельца.
- `/revoke <telegram_user_id>` — отозвать доступ пользователя; только для владельца.
- `/users` — показать разрешённые Telegram ID; только для владельца.
- Любой другой текст после авторизации — новый поиск.

Владелец всегда остаётся в allowlist и не может быть отозван. Для других людей
используй именно числовой Telegram ID. Состояние меню, callback-кнопки и поиск
изолированы по пользователю и личному чату; кнопка из чужого или устаревшего меню
не должна выполнять действие в другом диалоге.

### Список «Смотрю» и прогресс

После выбора аниме его можно добавить в «Смотрю». Для сохранённого тайтла бот хранит
его идентификатор Anime365, название, дату добавления, последнюю просмотренную серию
и настройки уведомлений. Поэтому `/watching` открывает список сразу по сохранённому
`series_id`, без поиска по названию. Из карточки можно открыть серии, выбрать
«Продолжить» или удалить тайтл из списка. «Продолжить» выбирает первую доступную
серию после сохранённого прогресса.

Прогресс меняется только после успешной отправки готового видео в Telegram. После
отправки можно перейти к следующей серии или вернуться к «Смотрю»; неудачная загрузка,
отмена и ошибка отправки не отмечают серию просмотренной.

Mini App дополнительно хранит позицию, длительность и время обновления для текущей
серии. Клиент отправляет их примерно раз в 15 секунд, на паузе и при завершении;
на 90% длительности или при `ended` серия также обновляет совместимые
`last_watched_*` поля. Это сохраняет поведение `/watching` и «Продолжить» в боте.

В карточке тайтла Mini App также позволяет включить уведомления о любой новой
серии, русских субтитрах или русской озвучке, отключить их и удалить тайтл из
«Смотрю». При включении текущий список серий становится baseline, поэтому старые
релизы не присылаются повторно. Кнопка «Смотреть в Mini App» в Telegram
уведомлении передаёт только внутренние `series_id` и `episode_id`, открывая выбор
перевода для конкретной серии; токены и временные media URLs в ссылку не попадают.

### Offline через Mini App

После выбора качества доступны «Скачать» и «В Telegram». Обе команды ставят
существующий `MediaProcessor` в ограниченную очередь: `yt-dlp`, внешний subtitle
и `ffmpeg` remux с `-c:v copy -c:a copy`; видео не перекодируется. Browser-файл
получает короткоживущий owner-bound URL только после готовности и удаляется после
`DOWNLOAD_TTL`. Задачу можно отменить через API; при restart незавершённая задача
безопасно возвращается в очередь, а временные каталоги очистятся.

Экран «Загрузки» группирует задачи по тайтлу и показывает серию, качество,
назначение и состояние. «Скрыть завершённые» убирает готовые, отправленные,
отменённые и неудачные задачи только из интерфейса: строки, имя тайтла и вся
история остаются в SQLite. Активные задачи эта кнопка не затрагивает.

Кнопка «В поездку» после выбора перевода и качества добавляет следующую серию,
следующие 3/5 или все непросмотренные в ту же очередь. ID перевода у Anime365
относятся к конкретной серии, поэтому сервер заново ищет для каждой серии тот же
тип, язык и студию, а при отсутствии студии — другой доступный перевод того же
типа и языка. Неподходящие серии показываются до начала загрузки. За один запуск
планируется максимум 25 задач, чтобы случайный клик не переполнил VDS; остаток
можно добавить следующим запуском. Размер заранее не обещается и становится
известен только после загрузки.

### Shikimori OAuth

Без изменения кода бота список «Смотрю» можно связать с Shikimori отдельным
синхронизатором: он сопоставляет тайтлы и передаёт статус и число просмотренных
серий через [Shikimori API v2](https://shikimori.io/api/doc/2.0.html). Для этого
нужны отдельное OAuth-приложение Shikimori, настроенный `redirect_uri`, scope
`user_rates` и безопасное раздельное хранение `access_token` и `refresh_token`
каждого пользователя. Идентификатор Anime365 `series_id` не совпадает с
идентификатором Shikimori, поэтому соответствие тайтлов нужно подтверждать перед
синхронизацией.

Внешний сервис создаёт запись через `POST /api/v2/user_rates`, затем обновляет
её через `PATCH /api/v2/user_rates/:id`; для аниме передаются как минимум
`target_id`, `target_type: Anime`, `status` и `episodes`. Запросы должны содержать
имя OAuth-приложения в `User-Agent`, работать по HTTPS и соблюдать лимиты Shikimori:
до 5 запросов в секунду и 90 в минуту. OAuth-поток описан в
[руководстве Shikimori](https://shikimori.io/oauth), а методы списка — в
[документации user rates](https://shikimori.io/api/doc/2.0/user_rates.html).

Mini App уже поддерживает безопасное OAuth-подключение. Создай приложение
Shikimori, укажи redirect URI `https://<домен>/api/shikimori/callback` и заполни
все три `SHIKIMORI_*` переменные. Callback связан с Telegram-пользователем
одноразовым state, а access/refresh tokens хранятся зашифрованно тем же Fernet
ключом. Они не возвращаются в Mini App и не попадают в логи.

В Mini App можно выбрать статусы для импорта. Импорт сохраняет список отдельно от
локальной библиотеки; он не удаляет локальные данные. Уже известные связи
подхватываются автоматически. Для остальных тайтлов Mini App показывает кандидатов
Anime365: совпадение `myAnimeListId` ↔ `mal_id` помечается как проверенное, а любое
другое совпадение требует явного выбора пользователя. Автоматического fuzzy-match
по названию нет. При связке тайтл добавляется в «Смотрю», а число просмотренных
серий становится `max(local, shikimori)`; позиция внутри серии всегда остаётся
локальной.

После успешного просмотра серии локальный прогресс записывается первым. Для уже
привязанного тайтла Mini App затем best-effort обновляет только поле `episodes` в
Shikimori, не переводя статус в «Просмотрено» автоматически. Ошибка Shikimori не
мешает плееру и не отменяет локальное обновление.

### Уведомления о новых сериях

Уведомления включаются отдельно для каждого сохранённого аниме. Доступны три режима:
любая новая серия, новая серия с русскими субтитрами и новая серия с русской озвучкой.
Настройка режима меняется в карточке тайтла или через `/notifications`.

При включении бот фиксирует текущее состояние как исходное и не присылает все старые
серии. Фоновая задача выполняется с интервалом `WATCH_CHECK_INTERVAL` (по умолчанию
10 минут), получает список уникальных `series_id` и запрашивает серии один раз для
каждого тайтла, даже если за ним следят несколько пользователей. Для режимов с русским
переводом дополнительно проверяется список переводов конкретной серии: уведомление
уходит только после появления подходящих русских субтитров или озвучки.

Обнаруженные уведомления сначала записываются в SQLite, затем отправляются с кнопками
для просмотра серии, открытия аниме и отключения уведомлений. Базовое состояние,
кандидаты и очередь доставки сохраняются на диске, поэтому после перезапуска проверка
продолжается и уже отправленная серия не дублируется. Временная очистка меню не удаляет
уведомления о новых сериях. Ошибки Anime365 и Telegram обрабатываются повторными
попытками с ограниченной задержкой и не останавливают polling или загрузки.

Списки разбиты на страницы до восьми вариантов; есть «Назад» и «Отмена».
Результаты поиска показывают названия аниме, год и тип в тексте сообщения,
а выбор выполняется короткими кнопками с номерами. Длинные названия переносятся
на несколько строк, поэтому сезон в конце названия остаётся виден. Если страница
не помещается в лимит сообщения Telegram, на ней показывается меньше вариантов.
После выбора серии появляется меню типов просмотра: например, русские субтитры,
русская озвучка, английские субтитры, английская озвучка и оригинал (RAW).
Бот показывает только доступные для этой серии типы; другие языки и типы,
вернувшиеся из Anime365, также доступны. Затем выбирается студия/перевод или
версия оригинала, а после — качество. Кнопка «Назад» позволяет сменить тип просмотра.
После выбора качества меню показывает состояние подготовки, а готовый MKV приходит
как документ с описанием выбранной серии, типа перевода и качества.
Доступное качество берётся из embed API Anime365, для которого требуются токен
и активная подписка.

Входящие сообщения разрешённых пользователей удаляются сразу после получения. Меню обновляется
в одном сообщении, удаляется после успешной отправки или через 15 минут
бездействия. Уведомления об ошибках удаляются через минуту. После перезапуска
незавершённый выбор нужно начать заново; его старые сообщения также очищаются.
При ошибках удаления бот повторяет попытку, но сообщения старше 48 часов Telegram
обычно уже не разрешает удалить. Видео и чужую историю бот не очищает: он удаляет
только зарегистрированные сообщения своего рабочего диалога.

Токен Anime365 шифруется Fernet и хранится в SQLite вместе с Telegram ID.
Ключ `token.key` лежит отдельным файлом рядом с `bot.sqlite3` в Docker volume
`ani365_bot-data`, с ограниченными правами. Обновления сохраняют этот volume.
Для восстановления нужны **и база, и ключ**; доступ ко всему volume позволяет
расшифровать токен. В SQLite для списка и уведомлений хранятся только необходимые
идентификаторы, названия, прогресс и служебное состояние доставки, а не полные ответы
Anime365. Текст входящих сообщений, ответы API, токены и секретные URL не записываются
в логи или базу. `.env` исключён из Git и контекста Docker-сборки.

Для каждой загрузки создаётся отдельный каталог в volume `ani365_media-jobs`.
Исходное видео, субтитры и готовый MKV удаляются сразу после ответа Telegram,
в том числе при ошибке или отмене процесса. При старте бот удаляет все каталоги задач,
оставшиеся после предыдущего процесса. Файл в чате Telegram не регистрируется
в очереди удаления и остаётся доступен для просмотра. Логи контейнеров ограничены
тремя файлами по 5 МБ. Не выполняй `docker compose down -v`, если хочешь сохранить
авторизацию: `-v` удаляет базу, ключ и служебные данные локального Bot API.

Локальный Bot API доступен только внутри сети Compose и работает в режиме `--local`.
Именно он позволяет отправлять файлы до 2000 МБ. Бот читает MKV из своего временного
volume и передаёт его потоковым `multipart/form-data`, не загружая весь файл
в оперативную память. Временный файл при приёме хранится в дисковом volume
`ani365_telegram-api-temp`, а не в RAM, и удаляется сервером Bot API после запроса.
Наружу порт 8081 не публикуется. Если итоговый файл достигает лимита, бот удаляет
его и предлагает выбрать более низкое качество.

Если подготовка файла завершилась ошибкой, посмотри безопасную диагностику утилит:

```bash
sudo docker compose logs --since=30m --tail=200 bot
```

Строка `Media tool yt-dlp failed` означает ошибку скачивания, а
`Media tool ffprobe failed` — некорректный скачанный вход, `Media tool ffmpeg failed` —
ошибку сборки MKV. Имя после `<media>/` показывает, не распознано видео или субтитры.
В журнал попадают код завершения
и очищенный текст ошибки; подписанные ссылки на видео заменяются на `<url>`.
Для сетевой ошибки Telegram журнал также показывает метод и этап `connect`, `upload`
или `response`. Обрыв до принятия запроса повторяется один раз автоматически.

### Ограничения данных Anime365

Anime365 не предоставляет отдельный push-канал о релизах, поэтому уведомление может
появиться только после очередной проверки и возможной повторной попытки. Номер и
доступность серии берутся из ответа `episodes(series_id)`. Для режимов «русские
субтитры» и «русская озвучка» бот опирается на `translations(episode_id)` и его
метаданные типа и языка (`type`, `typeKind`, `typeLang`); если перевод ещё не появился
или API вернул неполные/неоднозначные данные, уведомление откладывается до следующей
проверки. Такое уведомление означает, что Anime365 сообщил о подходящем переводе, но
не заменяет проверку доступа к embed-потоку: для загрузки по-прежнему нужны действующий
личный токен Anime365 и доступная подписка.

## Обновления через GitHub Releases

Этот режим можно подключить отдельно вместо ручной сборки из исходников.
Обновления устанавливаются по стабильным GitHub Releases с тегами вида
`bot-v0.1.0`. Каждый push/PR проходит тесты и проверку сборки. При публикации
релиза workflow дополнительно публикует образ
`ghcr.io/drumdrumspike/ani365-bot:bot-v0.1.0`.

После первой публикации в GitHub открой **Packages → ani365-bot → Package settings**
и установи видимость **Public**. Публичность репозитория не делает пакет публичным
автоматически. VDS скачивает публичные образы без GitHub-токена. Сам workflow
публикует образ через встроенный `GITHUB_TOKEN`; секреты Telegram ему не нужны.
Текущая сборка предназначена для VDS с архитектурой **x86_64/amd64**.

Установить опубликованный релиз вручную:

```bash
cd /opt/ani365-cli
sudo bash scripts/update.sh
```

Сообщение `No stable bot-vX.Y.Z release found; no update.` означает, что подходящий
релиз ещё не опубликован. Commit и push сами по себе не создают релиз.

Файл `deploy.env` создаётся update-скриптом после нахождения подходящего релиза.
До этого используй обычные команды `docker compose`, как в разделе ручного обновления.
После успешного перехода на релиз используй файл выбранной версии:

```bash
sudo docker compose --env-file deploy.env ps
sudo docker compose --env-file deploy.env logs --tail=50 bot
sudo docker compose --env-file deploy.env up -d --no-build
```

Для автоматической проверки каждые 15 минут:

```bash
sudo install -m 644 deploy/ani365-update.service /etc/systemd/system/
sudo install -m 644 deploy/ani365-update.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ani365-update.timer
sudo systemctl list-timers ani365-update.timer
```

Путь `/opt/ani365-cli` закреплён в service-файле. Если установлен в другом месте,
поменяй `WorkingDirectory` и `ExecStart` перед установкой service-файла.

Обновление сначала скачивает образ, затем временно блокирует новые поиски и ждёт
завершения текущего меню или его истечения. Через 20 минут ожидания откладывается.
Сохраняет выбранный digest в `deploy.env`, перезапускает контейнер и ждёт
положительной проверки здоровья. При неудаче возвращает предыдущий образ.
База и `.env` остаются на месте. Старые неиспользуемые образы этого бота удаляются;
образ предыдущей версии сохраняется под тегом `ani365-bot:rollback`.

Автообновление меняет **образ приложения**, а не системный Docker, Compose-файл
или сам update-скрипт. Изменения инфраструктуры устанавливаются отдельно из
репозитория. Миграции SQLite выполняются вперёд и сохраняют существующие данные;
перед сменой версии сохрани резервную копию `ani365_bot-data`. Образ предыдущей версии
может не понимать более новую схему, поэтому автоматический откат приложения не заменяет
восстановление базы из такой резервной копии.

Диагностика:

```bash
sudo journalctl -u ani365-update.service -n 50 --no-pager
sudo docker compose --env-file deploy.env exec -T bot python -m ani365_bot.control resume
```

Последняя команда снимает режим ожидания обновления, если обновляющий процесс
был аварийно завершён. Обычный выход скрипта снимает его автоматически.
Ни workflow, ни сервер не публикуют релиз самостоятельно — его создаёт владелец
репозитория после проверки изменений.

## Проверки разработки

Этот раздел нужен для разработки, а не для запуска или обновления бота на VDS.
Для тестов вне Docker на Ubuntu сначала установи поддержку виртуальных окружений:

```bash
sudo apt install -y python3-venv
```

Затем, с Python 3.12:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
bash -n scripts/update.sh
docker compose config --quiet
docker build -t ani365-bot:check .
```

На Ubuntu для создания venv нужен пакет `python3-venv`; для Docker-запуска он не нужен.
Тесты используют подставные ответы API, не читают `.env` и не отправляют сообщения.
Проверка на настоящем аккаунте: `/start` → токен Anime365 → поиск → серия → тип просмотра
→ перевод/версия → качество → получение MKV в чате; затем проверь отсутствие каталогов
`job-*` командой `sudo docker compose exec -T bot find /jobs -maxdepth 1 -type d`.
После этого перезапусти контейнер и повтори поиск без повторного ввода токена.

Для мультипользовательской проверки владелец добавляет второй тестовый ID через
`/allow`, а оба пользователя задают собственные токены Anime365. У каждого добавь
тайтл через поиск, проверь `/watching`, «Продолжить» после успешной отправки и
изменение режима уведомлений. После перезапуска контейнера убедись, что allowlist,
токены, список, прогресс и исходное состояние уведомлений сохранились. Повторная
проверка одной и той же новой серии не должна прислать дубликат. Отдельно проверь
`/revoke`, `/users`, `/logout` и отсутствие доступа с чужого ID.
