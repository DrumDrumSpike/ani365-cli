# Персональные рекомендации

Подбор запускается из Mini App и выполняется внутри процесса `web`. Отдельного
контейнера, Compose-профиля и systemd timer больше нет. ChatGPT и Grok
независимы: у каждого источника свой job и своя последняя удачная подборка.

## Данные

Миграция SQLite v15 удаляет таблицу `recommendation_items` вместе со старой
лентой и создаёт:

- `recommendation_jobs` — очередь `queued` / `running` / `ready` / `failed` на
  пару пользователь + источник. Одновременно активен только один job. Флаг
  `api_called` фиксируется до HTTP-запроса;
- `recommendation_picks` и `recommendation_pick_items` — история подборок,
  объяснения и отзыв на пару;
- `recommendation_continuations` — детерминированные сиквелы, не слоты модели.

После перезапуска `web` job без вызова API продолжается. Job, который уже
вызвал API и не успел сохранить ответ, помечается неудачным и не повторяет
запрос. Прошлая подборка остаётся.

## Вкус и кандидаты

В профиль входят статусы watching, completed и dropped; оценки rewatching и
on_hold тоже калибруются, если они есть. Медиана и разброс считаются по
completed. «Брошено» хранит исходную оценку и не меняет веса жанров. Отзыв на
пару тоже не меняет веса: он только контекст следующего промпта.

Пул личный. Жанры с положительным относительным весом дают разные годы, а не
только верх ranked. Кандидат остаётся, только если Anime365 подтверждает его
точный MAL ID. Shikimori id как MAL ID не используется. Исключаются весь список
Shikimori, локальная библиотека, уже рекомендованные id и продолжения
непросмотренных франшиз. В промпт уходит не больше `RECOMMENDATION_CANDIDATE_LIMIT`
карточек (по умолчанию 36, потолок 40).

Модель может вернуть 2, 1 или 0 id. Ответ принимается только если все id
различны и входят в переданный список. Иначе один повтор. Второй неверный ответ
помечает job как failed и сохраняет прошлую подборку.

Блок «Вышло продолжение» строится по связи Shikimori `sequel` у completed,
watching и rewatching. Сиквел не показывается, если он уже есть в списке
пользователя.

## Ключи и стоимость

Переменные только у сервиса `web`:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OPENAI_API_KEY` | пусто | ключ ChatGPT |
| `OPENAI_MODEL` | `gpt-5.4-mini` | Chat Completions, JSON schema, reasoning |
| `OPENAI_REASONING_EFFORT` | `medium` | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `XAI_API_KEY` | пусто | ключ Grok |
| `XAI_MODEL` | `grok-4.7` | Chat Completions, JSON schema, reasoning |
| `XAI_REASONING_EFFORT` | `medium` | у grok-4.7 нет `none`: `low`, `medium`, `high`, `xhigh` |
| `RECOMMENDATION_DAILY_LIMIT` | `5` | вызовов API на пользователя и источник за 24 часа |
| `RECOMMENDATION_CANDIDATE_LIMIT` | `36` | кандидатов в одном промпте |
| `RECOMMENDATION_LLM_TIMEOUT` | `180` | секунд на чтение одного ответа модели |

Цены на ноябрь 2026, стандартный контекст короче 200 тысяч токенов.
`gpt-5.4-mini`: $0.75 за 1M входных и $4.50 за 1M выходных, включая токены
рассуждения. `grok-4.7`: $2 и $6 за 1M. Для промпта около 3 тысяч токенов и
около 2.3 тысячи токенов ответа с reasoning уровня medium это примерно $0.012
за клик ChatGPT и $0.020 за клик Grok. 200 запусков одного источника — около
$2.50 и $4. Повтор при неверном JSON удваивает только этот клик. Лимит ответа
`max_completion_tokens` равен 4096, чтобы рассуждение не съело видимый JSON.

Ошибки на русском: нет ключа, 401, 429 или закончившийся баланс, таймаут,
недоступность, неверный ответ. Они не скрывают прошлую подборку этого источника.

## Mini App

`GET /api/recommendations` — оба источника, активный job, последняя подборка,
продолжения и остаток лимита. Без Shikimori кнопка подбора не показывается.

`POST /api/recommendations/{openai|xai}` — поставить job. Повтор во время
`queued` или `running` возвращает тот же job.

`POST /api/recommendations/{source}/feedback` — оценка пары 1–10 или пропуск и
отметки интересных тайтлов.

`GET /api/recommendations/history` — история подборок и отзывов. Она же
источник фильтра «не повторять».
