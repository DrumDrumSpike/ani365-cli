# Субтитры веб-плеера

HTML5 video и HLS остались прежними. Авторизованный `/api/subtitles/{ticket}`
возвращает ASS/SSA в UTF-8 без конвертации. Нормализация скачивания сохраняет
содержимое скрипта, распаковывая HTTP-сжатие и определяя кодировку. SSA также
распознаётся по содержимому и может иметь расширение `.ass` после нормализации.
SRT конвертируется FFmpeg в WebVTT; исходный VTT отдаётся без конвертации.

ASS/SSA рендерит локально поставляемый SubtitlesOctopus 4.1.0 (libass в WebAssembly,
с asm.js fallback). Полный скрипт поступает в worker через `subContent` после
авторизованного fetch. Позиционирование (`pos`, `move`, `an`), оформление
(`bord`, `shad`, `blur`), шрифты/цвета (`fs`, `fn`, `c`), рисунки (`p`), эффекты
(`t`, `fad`, `fade`), PlayRes, одновременные события и Layer обрабатывает libass.
Конвертации ASS в текст и удаления тегов нет. При ошибке libass выводится сообщение,
а не текстовая дорожка с утраченным оформлением.

Библиотека следует событиям видео: play/pause, seek, buffering, playbackRate.
При позднем завершении загрузки её часы инициализируются текущим временем видео.
ResizeObserver и обработчики fullscreen пересчитывают canvas по прямоугольнику
изображения с учётом чёрных полей и плотности пикселей. В fullscreen переводится
`.player-surface`, содержащий и video, и canvas. Если fullscreen элемента недоступен
(в том числе в некоторых iOS WebView), используется режим на всё окно/Telegram.
Видео-only fullscreen и PiP для ASS отключены, поскольку отдельная нативная
видеоповерхность не отображает HTML canvas. Для ASS есть отдельная кнопка субтитров;
для VTT/SRT доступны стандартные элементы video.

Встроенные в ASS шрифты поддерживаются libass. Для отсутствующих шрифтов поставляется
Liberation Sans с кириллицей. Совпадение нестандартного шрифта по одному имени `fn`
невозможно без самого файла: браузерный worker не имеет доступа к системным шрифтам.
Для конкретных релизов дополнительные лицензированные файлы можно подключить через
`fonts`/`availableFonts` в опциях SubtitlesOctopus. Шрифты из внешних MKV-вложений
не извлекаются, поскольку веб-плеер получает отдельный скрипт от CDN.

## Проверка

- `node --test tests/player.test.cjs`
- `.venv-314/bin/python -m unittest discover -s tests -p 'test_web.py'`
- Для браузерного теста нужны FFmpeg и Playwright с Chromium:
  `node --test tests/subtitles.browser.cjs` (пакет `playwright` должен быть доступен Node).

Браузерный тест использует `tests/fixtures/rendering.ass` и настоящий worker/WASM:
проверяет пиксели векторного рисунка вместо текста команд, цвета и слои,
движение после перемотки, масштабирование, общий fullscreen-контейнер,
исчезновение/возврат событий по времени и освобождение renderer.
