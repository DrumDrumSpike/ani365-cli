# Субтитры веб-плеера

HTML5 video и HLS остались прежними. Авторизованный `/api/subtitles/{ticket}`
возвращает ASS/SSA в UTF-8 без конвертации. Нормализация скачивания сохраняет
содержимое скрипта, распаковывая HTTP-сжатие и определяя кодировку. SSA также
распознаётся по содержимому и может иметь расширение `.ass` после нормализации.
SRT конвертируется FFmpeg в WebVTT; исходный VTT отдаётся без конвертации.

ASS/SSA рендерит локально поставляемый SubtitlesOctopus 4.1.0 (libass в WebAssembly,
с asm.js fallback). Полный скрипт поступает в worker через `subContent` после
авторизованного fetch. Позиционирование (`pos`, `move`, `an`), оформление
(`bord`, `shad`, `blur`), шрифты/цвета (`fs`, `fn`, `c`), рисунки (`p`), эффекты
(`t`, `fad`, `fade`), PlayRes, одновременные события и Layer обрабатывает libass.
Конвертации ASS в текст и удаления тегов нет. При ошибке libass выводится сообщение,
а не текстовая дорожка с утраченным оформлением.

Библиотека следует событиям видео: play/pause, seek, buffering, playbackRate.
При позднем завершении загрузки её часы инициализируются текущим временем видео.
ResizeObserver и обработчики fullscreen пересчитывают canvas по прямоугольнику
изображения с учётом чёрных полей и плотности пикселей. В fullscreen переводится
`.player-surface`, содержащий и video, и canvas. Если fullscreen элемента недоступен
(в том числе в некоторых iOS WebView), используется режим на всё окно/Telegram.
Видео-only fullscreen и PiP для ASS отключены, поскольку отдельная нативная
видеоповерхность не отображает HTML canvas. Для ASS есть отдельная кнопка субтитров;
для VTT/SRT доступны стандартные элементы video.

Встроенные в ASS шрифты поддерживаются libass. Для отсутствующих шрифтов поставляется
Liberation Sans с кириллицей. Совпадение нестандартного шрифта по одному имени `fn`
невозможно без самого файла: браузерный worker не имеет доступа к системным шрифтам.
Дополнительные шрифты подключаются из `DATA_DIR/subtitle-fonts/fonts.json`:

```json
{"verdana": ["regular.ttf", "bold.ttf", "italic.ttf", "bolditalic.ttf"]}
```

Ключ — настоящее имя семейства в нижнем регистре, значения — имена файлов
в этой же директории. `/api/play` передаёт список доступных семейств плееру;
он выбирает только использованные в стилях ASS/SSA и тегах `\fn` семейства,
включая все их начертания. Worker получает URL файлов через `fonts`, выбор
начертания остаётся за fontconfig/libass. Шрифты кешируются браузером.
Метрики, `Fontsize`, Bold/Italic, ScaleX/Y, обводки, тени и координаты не меняются.
При отсутствии каталога поведение остаётся прежним.

Установить уже имеющиеся оригинальные файлы можно командой (нужен `fc-scan`
из fontconfig только на машине установки):

```sh
python3 scripts/install_subtitle_fonts.py 'episode.ass' \
  --source /path/to/original/fonts --output data/subtitle-fonts
```

Можно указать несколько `--source`. Скрипт читает реальные имена семейств
из метаданных, сохраняет все доступные начертания без дубликатов и сообщает
об отсутствующих семействах. Он не подменяет шрифты аналогами и не скачивает их.
Файлы именуются по SHA-256, поэтому новая версия получает новый URL кеша.
В Compose сервис `web` подключает каталог хоста `./data/subtitle-fonts` в
`/data/subtitle-fonts` только для чтения. Он доступен приложению даже с
`read_only: true` и сохраняется при пересборке/пересоздании контейнера.
Путь хоста можно изменить через `SUBTITLE_FONTS_DIR` в `.env`; относительный
путь отсчитывается от `compose.yaml`. При отсутствии файлов шрифты не подключаются.
Файлы шрифтов хранятся отдельно от Git и образа; учитывайте условия их использования
при развёртывании. Системная установка шрифтов в контейнер не нужна: libass
работает в браузере, а `web` выдаёт ему файлы.

### Перенос в Docker на сервере

На машине с подготовленными шрифтами:

```sh
tar -czf data/subtitle-fonts.tar.gz -C data subtitle-fonts
scp data/subtitle-fonts.tar.gz user@server:/tmp/subtitle-fonts.tar.gz
```

После переноса обновлённого кода проекта выполните на сервере из каталога
с `compose.yaml` (при необходимости используйте `sudo`):

```sh
mkdir -p data
tar -xzf /tmp/subtitle-fonts.tar.gz -C data
chmod 755 data/subtitle-fonts
chmod 644 data/subtitle-fonts/*
docker compose up -d --build web
docker compose exec -T web python -c 'from pathlib import Path; from ani365_bot.subtitle_fonts import subtitle_fonts; print({k: len(v) for k, v in subtitle_fonts(Path("/data")).items()})'
```

Ожидаемый список: `arial: 4`, `georgia: 4`, `impact: 1`, `verdana: 4`.
Если используете свой `SUBTITLE_FONTS_DIR`, распакуйте архив в этот каталог.
Не копируйте файлы в `/usr/share/fonts` контейнера: worker браузера не использует
системные шрифты сервера. После обновления заново откройте серию в плеере.

Шрифты из внешних MKV-вложений не извлекаются, поскольку веб-плеер получает
отдельный скрипт от CDN. В предоставленном ASS секции `[Fonts]` нет;
самого исходного видео с вложениями для анализа нет.

### Проверка предоставленного Tempal, серия 1, t6022138

| Где | Семейство | Параметры стиля |
| --- | --- | --- |
| Основной / Курсив, внизу / вверху | Tahoma | 22, Outline 2.6, Shadow 1, обычный / курсив |
| Надписи | Arial | 20, Outline 2, Shadow 0 |
| Система | Verdana | 20, Bold, Outline 1, Shadow 0 |
| Переопределения `\fn` | Impact, Verdana, Georgia | параметры конкретных событий сохраняются |

В исходнике PlayRes и LayoutRes — 640×360. Доступны 13 оригинальных файлов:
Arial (4), Verdana (4), Georgia (4), Impact (1). Они установлены локально в
`data/subtitle-fonts`. Оригинальной Tahoma нет: найденный Wine Tahoma является
другой реализацией и не устанавливался. После загрузки этих четырёх семейств
fontconfig выбирает для Tahoma Arial/Arial Italic, поэтому диалоги всё ещё
могут отличаться от эталона. Оригинальные Tahoma Regular/Bold можно добавить
тем же установщиком — frontend менять не потребуется.

`audit_subtitle_fonts.cjs` запускает настоящий worker/WASM с полным ASS дважды:
только fallback и с установленными файлами. В диагностическом HTTP-сервере
включается verbose-журнал libass, production worker не меняется. Проверяются
реально выбранные файлы, а не только заданные опции. На 16 кадрах с разными
стилями/переопределениями подтверждены Verdana/Verdana-Bold, ArialMT/Arial-BoldMT,
Impact, Georgia-Bold; с одним fallback все заменялись на Liberation Sans.
Пиксели изменились на 16 из 16 кадров. Это подтверждает смену шрифтов;
полное визуальное совпадение с сайтом без Tahoma не утверждается.

```sh
node scripts/audit_subtitle_fonts.cjs 'episode.ass' data/subtitle-fonts
```
Требуется Playwright с Chromium, доступный Node. Видеопоток не скачивается.

## Проверка

- `node --test tests/player.test.cjs`
- `.venv-314/bin/python -m unittest discover -s tests -p 'test_web.py'`
- Для браузерного теста нужны FFmpeg и Playwright с Chromium:
  `node --test tests/subtitles.browser.cjs` (пакет `playwright` должен быть доступен Node).

Браузерный тест использует `tests/fixtures/rendering.ass` и настоящий worker/WASM:
проверяет пиксели векторного рисунка вместо текста команд, цвета и слои,
движение после перемотки, масштабирование, общий fullscreen-контейнер,
исчезновение/возврат событий по времени и освобождение renderer.
